本项目基于 Super Productivity 官方仓库 Fork 构建，专为长期个人稳定使用而设计，融合了 **静态托管**、**本地安全桥接**、**高可靠自动历史备份**、**独立迷你计时窗口** 与 **官方 SuperSync 云端同步**。

## 一、核心组件设计

### 1. 网页前端 (GitHub Pages)
- **部署方式**：通过 GitHub Actions 自动化工作流构建为无状态纯静态文件，发布至 GitHub Pages。
- **数据存储**：完全在用户本地浏览器 IndexedDB (`superProductivity`) 与 LocalStorage 中持久化。
- **隐私保护**：公开仓库与静态网站不包含任何用户个人任务、笔记或认证凭据。
- **SPA 路由**：自动生成 `404.html` 降级，刷新或直接访问子路径不发生 404 错误。

### 2. 本地桥接助手 (`local-bridge/`)
解决浏览器“无法随意读写本地磁盘”以及“网页关闭后无法执行 JS”的根本限制：
- **运行环境**：基于 Python 3 原生标准库（零第三方 pip 依赖），极低 CPU（~0.0%）与内存（~15MB）占用。
- **安全保障**：
  - 仅监听 `127.0.0.1`，绝不对局域网或公网暴露。
  - 严格校验 `Host` 标头（阻止 DNS Rebinding 攻击）。
  - 支持 Chromium Private Network Access (PNA) 协议（响应 `Access-Control-Allow-Private-Network: true`）。
  - 基于随机生成的 256 位 `X-Bridge-Token` 认证，杜绝未授权页面读取或写入。
  - 路径遍历防护（拒绝用户指定路径，所有备份均强制存入由受控命名规则生成的目标文件）。

### 3. 高可靠自动备份系统 (`backup_manager.py`)
- **双重触发机制**：
  1. 周期性调度：每 15 分钟由前端状态检测机制自动提取完整数据快照 (`AppDataComplete`)。
  2. 离线前守护：在页面关闭或刷新 (`beforeunload`) 时通过 `navigator.sendBeacon` 触发最终备份。
- **写入可靠性保证**：
  1. **数据健全性校验**：必须包含核心实体（tasks, projects 等），拒绝空数据或损坏数据覆盖旧备份。
  2. **临时文件与原子替换**：先写入 `.tmp_backup_<uuid>.json`，执行 `flush()` 与系统级 `fsync()`。
  3. **SHA-256 完整性核验**：写入完成后读取磁盘物理内容比对哈希值，确保无截断、无坏块。
  4. **原子替换**：使用 `os.replace` 原子覆写最终文件，进程崩溃或断电不会产生半截损坏文件。
- **历史版本与轮换策略**：
  - 默认保留最新 50 份完整历史版本，支持 30 天轮换。
  - **安全红线**：旧备份清理前必须确保新备份已成功落地并验证；任何情况下不得清理至 0 份。

### 4. 独立桌面迷你计时窗口 (`mini_window.py`)
- **独立浮窗**：可在阅读学习资料、查阅文档时在屏幕角落常驻显示。
- **展示内容**：当前活跃任务名称、已消耗时间、计时状态（正在计时 / 暂停 / 离线）、备份就绪标志。
- **防漂移墙钟计算**：计时显示基于真实基准时间戳 `(now - started_at)` 计算，绝不因前端后台节流产生累计误差。
- **双向联动**：点击浮窗上的“开始/暂停”按钮，指令通过桥接队列下发，网页端自动执行联动。
- **置顶与记忆**：支持一键切换“始终置顶”，退出前自动在 `config.json` 记忆窗口坐标 `(x, y)` 与尺寸。

## 二、浏览器后台运行限制与处理机制

| 场景 | 浏览器行为 | 系统的应对机制 |
| :--- | :--- | :--- |
| **标签页切到后台** | Chromium 节流 `setInterval` 至 1 分钟甚至冻结 | 1. `GlobalTrackingIntervalService` 采用墙钟差值 `(Date.now() - start)` 计算，重新激活时全量补偿；<br>2. 监听 `visibilitychange` 事件，恢复前台瞬间强制触发补偿 tick 并同步本地浮窗。 |
| **浏览器窗口最小化** | JS 执行被降频，渲染停止 | 迷你浮窗运行在操作系统原生进程中，依据基准时间戳独立刷新，时间显示丝毫不卡顿。 |
| **浏览器被完全关闭** | 浏览器 JS 彻底停止运行 | 1. 关闭前 `beforeunload` 发出信标完成最终保存；<br>2. 本地浮窗立即提示“⚠ 网页未连接”，诚实反映状态，绝不伪造虚假计时；<br>3. 已持久化的历史备份完好无损，随时可一键拉起网页恢复。 |
| **电脑休眠 / 睡眠唤醒** | 系统时钟中断 | 唤醒后系统级 `focus` 与 `DAY_CHANGE` 事件自动对齐时间，检测隔夜并提示结算。 |

## 三、云端同步与备份的关系界定

- **SuperSync 同步服务**：负责多设备间的实时/近实时数据流转（基于 Event Sourcing 的 Operation Log）。同步服务旨在保证各端最终一致性，但不是完备的历史快照备份系统（若某端错误清空任务，该操作也会同步）。
- **本地历史备份系统**：每次生成完全独立、只读的快照存档，用于应对误操作、误删除、设备损坏或云端故障时的精准时间点回滚（Point-in-Time Recovery）。
